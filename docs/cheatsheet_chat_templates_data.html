💬 Chat Templates & Data Prep — tokens, equations, tables, structured content & tools

The data backbone of fine-tuning. A model only understands its own chat template; get the tokens, special characters, equations and tool format right at prep time or training silently learns the wrong thing. Family tokens verified May 2026.

① What a chat template actually does
msgs = [{"role":"system","content":"You are concise."},
        {"role":"user",  "content":"What is DFT?"}]

text = tok.apply_chat_template(msgs, tokenize=False,
                                  add_generation_prompt=True)
# <|im_start|>system\nYou are concise.<|im_end|>
# <|im_start|>user\nWhat is DFT?<|im_end|>
# <|im_start|>assistant\n     ← model writes after this
It's a Jinja template stored on the tokenizer (tok.chat_template) that turns a message list into the exact token stream the model saw in post-training. Wrong template = degraded, weird outputs. Never hand-concatenate role strings. Always go through apply_chat_template so you inherit the model's exact tokens.

Alternation rules differ: Gemma-3 forces strict user/assistant alternation; SmolLM3 keeps only the first system message; Qwen is permissive. Validate on a sample before training a batch.
③ Tool / function calling format
tools = [{"type":"function", "function":{
  "name":"get_energy",
  "description":"DFT total energy",
  "parameters":{"type":"object",
    "properties":{"molecule":{"type":"string"}}}}]

text = tok.apply_chat_template(msgs, tools=tools,
                add_generation_prompt=True, tokenize=False)
# Model emits, e.g. (ChatML/Qwen-style):
# <tool_call>{"name":"get_energy","arguments":{...}}</tool_call>
Pass tools via the tools= arg — the template injects the schema. To train tool use, your data needs assistant turns containing the tool-call block + a role:"tool" turn with the result. Tool-calling is emergent with scale: a 1–3B can learn the format; a 135M usually can't. Don't fine-tune capability that isn't there.
④ add_generation_prompt: train vs infer
# INFERENCE: open the assistant turn, model continues
tok.apply_chat_template(msgs, add_generation_prompt=True)

# TRAINING (full convo incl. the answer): no gen prompt
tok.apply_chat_template(full_msgs, add_generation_prompt=False)
Base (non-instruct) models have no chat template — feed raw text, let them continue. Using a chat template on a base model (or vice-versa) is a silent quality killer. For SFT with assistant_only_loss, the template must mark assistant spans with {% generation %}…{% endgeneration %}.
⑤ The 3 data shapes you'll prepare
# raw text → CPT (full loss)
{"text": "Coupled cluster theory expands ..."}

# prompt/completion → SFT (completion-only)
{"prompt":"...", "completion":"..."}

# messages → chat SFT (assistant-only)
{"messages":[{"role":..., "content":...}, ...]}
Clean every corpus: NFKC normalize, strip boilerplate, and dedupe by content hash (redirects/mirrors silently over-weight topics). Quality > quantity for SFT.
⑥ New tokens — usually you DON'T need them
# FIRST CHECK: does the tokenizer already cover it?
len(tok(r"$\hat{H}\psi = E\psi$").input_ids)   # LaTeX = ASCII → fine

# Only if you add a genuinely new symbol/control token:
tok.add_special_tokens({"additional_special_tokens":["<rxn>"]})
model.resize_token_embeddings(len(tok),
                            mean_resizing=True)  # init new rows at the embedding mean
LaTeX, JSON, HTML, code, chemical formulae are plain ASCII — the BPE tokenizer handles them. Adding tokens you don't need just dilutes training. If you DO add tokens: mean_resizing=True places new rows on the pretrained manifold (better than random). It's simple but collapses new tokens into one subspace — fine for a few control tokens, risky for many.
⑦ When to train embeddings (embed_tokens + lm_head)
# Add them to LoRA targets ONLY when:
#  • CPT shifts the token distribution a lot (new domain/notation)
#  • you added new tokens (their rows start ~random)
target_modules = ["q_proj","k_proj","v_proj","o_proj",
                  "gate_proj","up_proj","down_proj",
                  "embed_tokens", "lm_head"]   # ← CPT

# Give embeddings a SMALLER LR so they don't destabilise
embedding_learning_rate = 5e-6   # vs 5e-5 base (Unsloth supports this)
For plain SFT on existing tokens, leave them out — tuning the big embedding/head on tiny data overfits and bloats the adapter (e.g. 116 MB → 1.2 GB).
⑧ Equations (LaTeX) — keep, don't garble
# Wikipedia renders math TWICE: a broken glyph dump AND
# clean LaTeX in {\displaystyle ...}. Keep the LaTeX, drop the glyphs.
# Use a BALANCED-BRACE scan (LaTeX nests {}): a regex truncates it.
latex = extract_between_balanced(text, r"{\displaystyle")
clean = f" $ {latex} $ "           # store inline as $...$
Represent math as inline $LaTeX$ (ASCII) — no new tokens, the model reads it as text, and it round-trips to rendered math downstream. Garbled glyph soup (e.g. "Ĥψ=Eψ" pulled from a PNG alt-text) teaches noise. Always inspect a few raw samples before training.
⑨ Tables, HTML, JSON & structured output
# Keep structure the model can reproduce: Markdown tables / fenced JSON
completion = """| method | scaling |
|--------|---------|
| HF     | N^4     |"""

# For guaranteed-valid JSON output, constrain at INFERENCE
# (don't rely on SFT alone): grammars / structured outputs
#   llama.cpp: --grammar  | Ollama: format:"json" | vLLM: guided_json
Strip presentational HTML (<div>, styles) from training text — it's noise. Keep semantic structure (tables, lists, code fences) if you want the model to emit it. Be consistent: pick one structure (Markdown or JSON) for a given task and use it across every example. Mixed formats confuse a small model.
⑩ Special characters & encoding hygiene
import unicodedata
clean = unicodedata.normalize("NFKC", raw)  # canonical form
# NFKC folds look-alikes: ﬁ→fi, full-width →ASCII, odd spaces→space
Normalize once at prep time so "café" and "café" (combining vs precomposed) don't become different token sequences. Keep meaningful Unicode (μ, Å, ψ) — modern BPE handles it. Watch invisible chars: NBSP ( ), zero-width (​), BOM. They sneak in from PDFs/web and blow up token counts.
⚡ Data-prep decision flow
1. Pick the data shape → it picks the loss (text=full, prompt/completion=completion-only, messages=assistant-only).  2. Render through the model's own apply_chat_template.  3. New token? Almost never — LaTeX/JSON/HTML are ASCII. If yes → add_special_tokens + resize_token_embeddings(mean_resizing=True) + train embed_tokens/lm_head.  4. NFKC, dedupe, strip boilerplate, eyeball 5 samples.
