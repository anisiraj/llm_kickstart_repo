🧬 Data Gen · Model Merging · Push-to-HF — scale your data, fuse models, ship to the Hub

The three "force-multiplier" steps once your pipeline works: generate more training data with an LLM, merge several fine-tunes into one, and publish adapters, merged models and datasets so they're reusable and citable.

① Synthetic data — the methods
MethodIdea
Distillationstrong teacher writes completions for your prompts
Self-Instructseed tasks → LLM generates more tasks+answers
Evol-InstructLLM rewrites prompts harder/deeper
Magpieprompt-only: aligned LLM emits its own queries
SFT data is scarce and expensive to hand-write — synthesis closes the gap. Best for clear, checkable tasks; pair with human-written seeds for your domain. Mind licenses: many model EULAs restrict using their outputs to train competitors. Check before distilling.
② Distillation (teacher → data)
from openai import OpenAI          # or a local vLLM/Ollama endpoint
client = OpenAI()

def make_pair(question):
    r = client.chat.completions.create(model="strong-model",
        messages=[{"role":"user","content":question}], temperature=0.4)
    return {"prompt":question, "completion":r.choices[0].message.content}
Feed it your domain questions (or generate questions from your corpus headings); keep a strong model's answers as gold completions. Cheapest way to bootstrap an SFT set.
③ Self-Instruct / Evol-Instruct loop
seed = load_seed_tasks()      # ~10–50 human examples
for _ in range(rounds):
    few = random.sample(seed, 6)
    new = llm(f"Here are tasks:\n{few}\nWrite 5 NEW, diverse tasks + answers")
    seed += dedupe(parse(new))      # rouge/embedding dedupe vs pool
Few-shot the model with seeds, ask for new diverse tasks, dedupe, repeat. Evol-Instruct instead asks the model to make each prompt harder (add constraints, deepen reasoning). Diversity is everything — without aggressive dedupe you get thousands of near-clones.
④ Magpie (prompt-only self-synthesis)
# Feed ONLY the template up to the user slot; the aligned
# model "completes" a plausible user query, then you ask
# it to answer that query → a full (prompt, completion) pair.
pre = "<|im_start|>user\n"           # nothing after it
q = model.generate(pre, stop="<|im_end|>")   # it invents the question
a = model.chat(q)
Cheap, no seeds, surprisingly strong for general alignment. Weaker where the base distribution rarely surfaces the task (e.g. niche math) — there, prefer seeded distillation.
⑤ ⚠ Quality control (the real work)
Decontaminate: remove any synthetic item overlapping your eval/test set or you'll measure leakage, not learning. Dedupe (exact + near, via embeddings/MinHash), filter (length, language, refusal, format), and judge a sample (LLM-as-judge or human) for correctness. Synthetic data inherits the teacher's errors and style. 200 clean, verified pairs beat 5,000 noisy ones for a small model.
⑥ Model merging — methods
MethodWhat it does
Linearweighted average of weights
SLERPspherical interp of 2 models (keeps geometry)
Task Arithmeticadd/subtract "task vectors" (Δ from base)
TIEStrim + sign-elect to cut interference (many models)
DARErandom-drop + rescale task vectors
Merging fuses several fine-tunes into one model with zero training — combine a chemistry tune + a code tune, or average checkpoints for robustness. Models must share the same base/arch.
⑦ mergekit — config + run
# merge.yaml  (TIES example)
merge_method: ties
base_model: HuggingFaceTB/SmolLM3-3B-Base
models:
  - model: user/chem-sft
    parameters: {weight: 0.5, density: 0.6}
  - model: user/code-sft
    parameters: {weight: 0.5, density: 0.6}
parameters: {normalize: true}
dtype: bfloat16

pip install mergekit
mergekit-yaml merge.yaml ./merged --cuda
Density = fraction of task-vector kept (TIES/DARE). Start equal weights, then tune. Output is a normal HF model — deploy it like any other.
⑧ Push to HF — adapters & models
from huggingface_hub import HfApi
api = HfApi()                        # reads HF token from login/env

api.create_repo("user/Model-LoRA", exist_ok=True)
api.upload_folder(repo_id="user/Model-LoRA", folder_path="adapter/",
    allow_patterns=["adapter_*","*.json","*.md"])   # skip optimizer state

# or, straight from training objects:
model.push_to_hub("user/Model-LoRA"); tok.push_to_hub("user/Model-LoRA")
Push the small adapter (≈100 MB) for reuse and the merged model for direct deploy. allow_patterns keeps multi-GB checkpoints/optimizer states out of the repo.
⑨ Push the dataset + a model card
api.create_repo("user/my-data", repo_type="dataset", exist_ok=True)
api.upload_folder(repo_id="user/my-data", repo_type="dataset",
                  folder_path="data/")

# README.md with YAML frontmatter = the model/dataset card
# ---\nlicense: apache-2.0\nbase_model: ...\ndatasets: [user/my-data]\n---
A good card (license, base_model, datasets, measured numbers, repro command) makes artifacts discoverable and trustworthy. Cross-link adapter ↔ dataset ↔ merged model. Never upload tokens/keys or licensed raw data. Wikipedia text → attribute CC BY-SA.
