Learning Philosophy

AI-Powered, Self-Driven
Nano Bootcamps

Traditional learning paths front-load syntax and defer building. That's backwards. In today's landscape, AI handles syntax — what you actually need is a solid grip on fundamentals, a real problem you care about, and the willingness to start before you feel ready.

Depth isn't pre-loaded from a course — it arrives on demand, driven by the specific wall you hit while building your thing. That's far more efficient, and it actually sticks.

Step 1
Grasp the fundamentals
How does a tensor flow through a model? What is a loss? What does a tokenizer actually do? These concepts are load-bearing — syntax isn't.
Step 2
Pick a problem you own
A domain, a dataset, a frustration. Not a tutorial problem — yours. Ownership creates the motivation that carries you through the hard parts.
Step 3
Build headfirst with AI
Start. Use an AI assistant to handle boilerplate, look up APIs, and unblock you in real time. You set the direction; AI handles the syntax.
Step 4
Let the problem teach you
OOM error → you learn quantisation. Hallucinating outputs → you learn alignment. Depth arrives exactly where you need it, when you need it.

⚙️ Quick Setup

Why two venvs?

Unsloth pins trl<0.9, which is incompatible with DPO/ORPO/GRPO trainers (need trl≥1.0). .venv handles Unsloth+SFT; .venv-rl handles alignment methods. 

# One-shot setup (CUDA GPU required)
bash scripts/setup_envs.sh

# Or manually:
uv venv .venv    # SFT + Unsloth
uv venv .venv-rl # DPO / ORPO / GRPO

# Run scripts
.venv/bin/python    scripts/verify_all.py
.venv-rl/bin/python scripts/verify_all.py

# Notebook kernels (registered automatically)
# Ctrl+Shift+P → Notebook: Select Kernel
#   → Python (.venv — Unsloth+SFT)      for sections 1-6
#   → Python (.venv-rl — DPO/ORPO/GRPO)  for sections 7-9
🧭 Which fine-tuning method should I use?
Full comparison table → Handbook §7
🎓
Causal LM / Pretrain
Domain adaptation on raw text. Shifts the model's knowledge before SFT. No labels needed.
Trainer + DataCollatorForLM
📋
SFT
Teach instruction-following from prompt/response pairs. First step for any assistant. Use Unsloth for speed.
SFTTrainer
🏆
DPO
Align to human preferences from chosen/rejected pairs. Run after SFT. No reward model needed.
DPOTrainer
⚡
ORPO
SFT + alignment in one pass from a base model. No reference model, less memory, faster.
ORPOTrainer
🧮
GRPO
RL from verifiable rewards. Best for math, code, structured output. Powers DeepSeek-R1.
GRPOTrainer
☁️ SageMaker & Bedrock are cloud execution engines — not training methods. Run any of the methods above on SageMaker for scale, or use Bedrock for managed FM inference. See chapters 8–9 in the handbook.
