Best Is Not Always Better.

Yes, large models with massive context windows can pull in knowledge at inference time. But they're not appropriate for everything. Learn it on Saturday, deploy it on Monday.

Why Fine-Tune? The case for small, specialized models
Edge & Embedded
Medical devices, HVAC controllers, drones, cars — you can't call an API at 30,000 feet. The model runs on the device or it doesn't run.
Cost & Latency
A 1B model serving 10M requests/day costs a fraction of API calls. Sub-10ms inference, no rate limits, no vendor lock-in.
Privacy & Compliance
Patient records, financial data, classified ops — some data can never leave your infrastructure. The model comes to the data.
AI Maturity
Calling an API is consuming AI. Fine-tuning is building AI capability. That's the difference between using a tool and owning the toolchain.
"A 400B model knows everything about nothing you do. A 1B model trained on your data knows exactly what matters."
Learning Philosophy AI-Powered, Self-Driven Nano Bootcamps
1. Fundamentals
Tensors, loss, tokenizers — the concepts, not the syntax.
2. Your Problem
Pick a real problem you own. Ownership drives motivation.
3. Build with AI
Start before you're ready. AI handles syntax; you set direction.
4. Depth on Demand
OOM → learn quantisation. Bad outputs → learn alignment.
"Pick the destination, then use every tool available to get there — including AI."

🧭 Which method?
🎓 Causal LM / Pretrain
Domain adaptation on raw text. No labels.
📋 SFT (Supervised Fine-Tuning)
Prompt/response pairs. Use Unsloth for speed.
🏆 DPO (Direct Preference)
Chosen/rejected pairs. Run after SFT.
⚡ ORPO (SFT + alignment)
One pass from base. No reference model.
🧮 GRPO (RL from rewards)
Math, code, structured output. Powers DeepSeek-R1.
☁️ SageMaker & Bedrock are cloud engines, not methods. Ch. 8–9
