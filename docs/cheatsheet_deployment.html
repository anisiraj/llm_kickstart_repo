🚀 Deployment — from a LoRA adapter to a model serving locally

A fine-tune is useless until it runs. The path is always: merge → (convert) → quantize → serve. Pick the runtime by where it runs — transformers/vLLM on a GPU server, llama.cpp/Ollama on a laptop or edge box. Commands verified May 2026.

① Pick the runtime
RuntimeBest for
transformersquick test, scripts, training parity
vLLM / TGIGPU server, high throughput, OpenAI API
llama.cppCPU/edge, GGUF, full control
Ollamalaptop/edge, easiest, one Modelfile
GGUF (llama.cpp/Ollama) is the CPU/edge format; safetensors (transformers/vLLM) is the GPU-server format. You can keep both from one merge.
② Merge the LoRA (always step 1)
from peft import PeftModel
from transformers import AutoModelForCausalLM, AutoTokenizer

base = AutoModelForCausalLM.from_pretrained(BASE, torch_dtype="bfloat16")
model = PeftModel.from_pretrained(base, "adapter/").merge_and_unload()
model.save_pretrained("merged/", safe_serialization=True)
AutoTokenizer.from_pretrained(BASE).save_pretrained("merged/")
Converters and most servers won't read a PEFT adapter directly — merge first. Always save the tokenizer alongside the weights. Unsloth shortcut: model.save_pretrained_merged("merged", tok, save_method="merged_16bit").
③ transformers — simplest serve
from transformers import pipeline
pipe = pipeline("text-generation", "merged/",
               torch_dtype="bfloat16", device_map="auto")
out = pipe([{"role":"user","content":"What is DFT?"}],
           max_new_tokens=128, do_sample=False)
print(out[0]["generated_text"][-1]["content"])
Applies the chat template for you. Perfect for verifying the merge matches training. Not for high concurrency.
④ vLLM — GPU server, OpenAI-compatible
pip install vllm
vllm serve ./merged --port 8000
# serve the LoRA WITHOUT merging:
# vllm serve BASE --enable-lora --lora-modules chem=./adapter

curl localhost:8000/v1/chat/completions -d '{
 "model":"merged","messages":[{"role":"user","content":"Hi"}]}'
PagedAttention → very high throughput; drop-in OpenAI API for harnesses/agents. Can hot-swap LoRA adapters without merging.
⑤ llama.cpp — convert + quantize + serve
# 1. HF safetensors → F16 GGUF (Python, no build needed)
python llama.cpp/convert_hf_to_gguf.py merged/ \
   --outfile model-f16.gguf --outtype f16

# 2. quantize (needs the compiled binary)
./llama.cpp/llama-quantize model-f16.gguf model-Q4_K_M.gguf Q4_K_M

# 3. serve an OpenAI-compatible API
./llama.cpp/llama-server -m model-Q4_K_M.gguf -c 4096
Runs on pure CPU; offload layers to GPU with -ngl N. Constrain JSON output with --grammar.
⑥ Ollama — easiest local serve
# Modelfile
FROM ./model-Q4_K_M.gguf      # or FROM ./merged (Llama-arch safetensors)
PARAMETER temperature 0.3
PARAMETER stop "<|im_end|>"      # the model's end-of-turn token!
SYSTEM "You are a concise chemistry assistant."

# build (quantizes on import), run, or hit the API
ollama create chem -q q4_K_M -f Modelfile
ollama run chem "What is DFT?"
curl localhost:11434/api/generate -d '{"model":"chem","prompt":"hi"}'
The stop token must match the model's chat template (e.g. ChatML <|im_end|>) or it rambles past the answer.
⑦ Unsloth — one-call GGUF export
# merge + convert + quantize in one go
model.save_pretrained_gguf("gguf", tok, quantization_method="q4_k_m")

# or straight to the Hub (multiple quants)
model.push_to_hub_gguf("user/Model-GGUF", tok,
                        quantization_method=["q4_k_m","q8_0"])
# then: ollama run hf.co/user/Model-GGUF
Bundles the merge + llama.cpp steps. Handy when you trained in Unsloth anyway.
⑧ ⚠ Architecture decides your path
Llama-architecture models (Llama, MiniCPM5, many Qwen) → Ollama imports the safetensors directly: FROM ./merged. No GGUF step. A newer/unsupported arch (e.g. SmolLM3ForCausalLM) → Ollama can't read the safetensors. You must convert_hf_to_gguf.py first, then FROM ./model-f16.gguf. Check arch support before you pick a base model. convert_hf_to_gguf.py supports a fixed list of architectures — if yours errors, update llama.cpp or wait for support.
⑨ Quantization levels — size vs quality
Quantbits/wtUse
Q8_0~8.5near-lossless, biggest
Q5_K_M~5.5high quality
Q4_K_M~4.8default — best size/quality
Q3_K_M~3.9tight RAM, quality drops
IQ2/Q2_K~2.6last resort
Footprint ≈ params × bits/8. A 3B at Q4_K_M ≈ 1.9 GB; a 1B ≈ 0.7 GB. Below ~Q3 quality falls fast on small models.
⑩ Edge & measuring honestly
# same Modelfile runs on a Raspberry Pi / Jetson via Ollama.
# tok/s from the API, NOT a stopwatch:
tok_s = eval_count / (eval_duration / 1e9)
Pick a model whose Q4_K_M footprint fits RAM with headroom (KV-cache grows with context). 1–3B is the sweet spot for laptops/Pi-class boards. Measure throughput on a normal-length answer. A barely-trained model that emits EOS immediately yields a meaningless 1-token "speed."
