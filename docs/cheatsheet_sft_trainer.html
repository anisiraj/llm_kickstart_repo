🎯 SFT Trainer — TRL loss masking, batching & QLoRA, the parts that bite

Supervised fine-tuning with 🤗 trl.SFTTrainer. The whole game is which tokens carry the loss and what your effective batch actually is. Verified against TRL 1.x / 0.2x behaviour; every claim has a one-line check you can run.

① The 3 loss modes — pick before anything else
ModeLoss onUse for
full causalevery tokenCPT / pretraining on raw text
completion-onlycompletion, prompt maskedSFT on prompt→completion pairs
assistant-onlyonly assistant turnsmulti-turn chat (mask user + system)
Masked tokens get label -100 → PyTorch CrossEntropyLoss(ignore_index=-100) skips them. "Masking" here means masking the loss, not attention. Why mask the prompt? You don't want the model learning to generate questions. Train it to write questions and at inference it'll "echo the prompt back" before answering — the #1 SFT bug.
② Dataset format auto-selects the masking
# TRL infers the recipe from your columns:

# (a) language modeling — one "text" field → FULL loss
{"text": "Density functional theory ..."}

# (b) prompt-completion → COMPLETION-ONLY loss (default!)
{"prompt": "What is DFT?",
 "completion": "A method that ..."}

# (c) conversational → use assistant_only_loss=True
{"messages": [{"role":"user",    "content":"What is DFT?"},
              {"role":"assistant","content":"A method ..."}]}
For a prompt-completion dataset, completion_only_loss defaults to True — the prompt is masked for you. (TRL docs.)
③ completion_only_loss — & how to PROVE it
from trl import SFTConfig, SFTTrainer

trainer = SFTTrainer(
    model=model, train_dataset=qa_pairs, processing_class=tok,
    args=SFTConfig(
        completion_only_loss=True,   # mask the prompt
        packing=False,               # packing can blur the mask — keep off for SFT
        max_length=1024))

# PROOF: pull ONE real collated batch, count non-(-100) labels
lab = next(iter(trainer.get_train_dataloader()))["labels"]
print((lab != -100).float().mean())   # ~0.6–0.8 (SFT). 1.0 means NOTHING is masked!
If that number is 1.0 your prompt isn't masked — wrong dataset format or flag. Fix before you waste a training run.
④ assistant_only_loss (multi-turn chat)
args = SFTConfig(assistant_only_loss=True)  # default False

# REQUIRES the chat template to mark assistant spans with
# {% generation %} ... {% endgeneration %} so TRL knows
# which tokens are the assistant's. Most modern templates do.
Masks system + every user turn; trains only on assistant replies — the right choice for multi-turn data so the model isn't penalised for "predicting" the user. Silently ignored if use_liger_kernel=True (known TRL issue) — loss falls back to the whole sequence. Verify with the same non-(-100) count.
⑤ Batch size × grad accumulation = the real knob
args = SFTConfig(
    per_device_train_batch_size = 2,   # fits in VRAM
    gradient_accumulation_steps = 8,   # accumulate before step
    # effective batch = 2 × 8 × num_gpus = 16
)
WantDo
↓ VRAMbatch 1, grad-accum ↑ (same effective batch, slower)
↑ speedbatch ↑ until OOM, grad-accum ↓
stable losskeep effective batch ~16–64 for SFT
Grad-accum is "fake" big batch: forward+backward on micro-batches, sum grads, step once. Mathematically ≈ one big batch — at the cost of more forward passes. Add gradient_checkpointing=True to trade ~20% speed for a big VRAM cut.
⑥ Canonical QLoRA (bitsandbytes 4-bit)
from transformers import BitsAndBytesConfig
import torch

bnb = BitsAndBytesConfig(
    load_in_4bit              = True,
    bnb_4bit_quant_type       = "nf4",        # NormalFloat4 (QLoRA paper)
    bnb_4bit_use_double_quant = True,         # quantize the quant constants too
    bnb_4bit_compute_dtype    = torch.bfloat16) # compute in bf16, store in 4-bit

model = AutoModelForCausalLM.from_pretrained(
    name, quantization_config=bnb, device_map="auto")
model = prepare_model_for_kbit_training(model)  # grad-ckpt + upcast norms
QLoRA = frozen base in 4-bit NF4, trainable LoRA adapters in bf16. ~6 GB for a 7–8B. The base never updates; gradients only flow to the adapters.

⑧ A canonical SFTConfig (annotated)
SFTConfig(
  output_dir                  = "out",
  num_train_epochs            = 3,        # tiny data → 2–4 epochs
  per_device_train_batch_size = 2,
  gradient_accumulation_steps = 8,        # eff. batch 16
  gradient_checkpointing      = True,
  learning_rate               = 2e-4,     # LoRA likes 1e-4–3e-4
  lr_scheduler_type           = "cosine",
  warmup_ratio                = 0.03,
  optim                       = "adamw_8bit",# 8-bit optimizer saves VRAM
  bf16                        = True,
  completion_only_loss        = True,
  packing                     = False,
  logging_steps               = 5,
  seed                        = 42)            # reproducibility
⚡ Decide in one glance
Raw text? → full loss (CPT).  Q&A pairs? → completion-only.  Multi-turn chat? → assistant-only.
OOM? → batch 1 + grad-accum↑ + grad-checkpointing + 4-bit NF4 + adamw_8bit.   Eff. batch = per_device × accum × gpus (aim 16–64).
Always verify the mask with the non-(-100) label count before a long run.  4-bit SFT casting errors? → use Unsloth.
